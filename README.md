# camtrapdesk

カメラトラップ調査のSDカードを、挿すだけで取り込み・検証・NAS転送し、野帳の対応表で地点名に付け替え、検証済みのカードだけ安全に消すためのデスクトップアプリ（Windows / macOS）。R パッケージ [camtrapdata](https://github.com/YoshihiroNakashima/camtrapdata) の SDカード系の関数（`rename_sd_volume`, `copy_from_sd`, `check_copy`, `delete_sd`, `rename_sd_to_station`）を GUI に移植し、台帳（SQLite + manifest.json）とハッシュ検証を加えたもの。

## 画面と流れ

左のメニューは、やる頻度で分かれている。保存先などの指定は各画面で行い、変えた値はその場で保存される（「設定を保存」ボタンは無い）。

**最初に一度だけ**
- **カードにIDを付ける** — 新しいSDカードの直下に id.txt（カードの番号）を書き込む。番号はカードに貼ったラベルと同じにする。任意で、ボリューム名（エクスプローラーに出る名前）もIDに合わせられる。id.txt を消してしまったカードは、取り込みのたびに覚えているボリュームシリアル（フォーマットしない限り変わらない番号）から前回のIDを候補に入れる。

**移行のたびに（この順で）**
1. **取り込み** — 画面の上で **保存先（中継）・NAS の最終保存先（任意）・取り込み先のフォルダ名・動画の変換のオンオフ** を指定する（変えるとすぐ保存される）。カードを挿すと自動で検出するが、起動直後は「開始待ち」で止まる。「取り込みを開始」を押すと保存先・フォルダ名・NAS・変換の有無が確認ダイアログに出て、Yes で挿さっているカードを始め、以後に挿したカードは自動で始まる（設定が違うまま勝手にコピーしないため。保存先やフォルダ名を変えると自動開始は止まり、もう一度確認する）。並列にコピーしてハッシュで検証。完了したカードは「抜いてOK」になる。ドライブ文字に依存しないので、20スロットを超えても扱える（Windows はボリュームGUIDパスで列挙）。検証済みのフォルダはバックグラウンドで NAS へコピーして読み戻し検証し、NAS に届かないときは待って再試行、再起動後も続きから。中継のコピーは既定で残す（控え）。中継の空きが足りないカードは「空き待ち」になり、別のSSDを繋いで保存先の欄を変えるとそちらへ続きから取り込む（コピー中にいっぱいになった場合も同様）。以前の中継SSDに残った分の NAS 転送は、そのSSDが繋がっているあいだに続き、ドライブ文字が変わっても中継先フォルダの目印（`.camtrapdesk-root.json`）で見つけ直す。中継を小さくしたいときは設定で「NASで検証済みになったカードは中継のコピーを自動で消す」をオンにできる。
2. **地点名に変更** — 野帳（Excel か csv）を指定すると自動で読み込む。使う行は「列 ＝ 値」の条件で絞り込む（例: Season ＝ 260710、Type ＝ N。複数はすべて満たす行。条件なしなら全行）。列は野帳の見出しから選び、値はその列にある値から選べる。条件は次回のために覚えておき、無ければ変更するフォルダ名に合う Season の値を初期値にする。変更するフォルダは保存先と NAS にある区切りフォルダの一覧から選ぶ。ドライランで、使う行の回収SD列とカードIDのフォルダを対応づけた結果（変更／保留／野帳に無い など）を一覧にし、「変更を実行」で中継と NAS の両方を変える。**設置記録との照合（任意）**: 「照合する」をオンにすると、設置時の表（野帳と同じファイルの前の調査回の行でも、別の csv/Excel でもよい）を「列 ＝ 値」で絞り込み、地点ごとの設置SD と今回の回収SD を比べる。合わない行には注意が付き（変更は止めない）、設置記録にあるのに回収行が無い地点も挙げる。設置SDの列名は設定（既定 InstallationSD）。
3. **カードを消す** — 画面を開くと挿さっているカードを自動で台帳と突合し、消せるか／消せない理由を一覧にする（NAS 転送が終わるたびに照合し直す）。「照合して、挿さっているカードを消す」の 1 ボタンで、保存先（NAS を使うなら NAS）に検証済みのコピーがあるファイルだけを消し、消さなかったカードは理由付きで知らせる。id.txt や台帳に無いファイルは残す。下の「取り込んだカードの消し忘れ」は台帳から、そのフォルダに取り込んだカードのうちまだ消していないものを ID で列挙するので、全部の移行が終わってからまとめて消す運用でも消し忘れを見つけられる。

**壊れたファイル（「スキャンして修復しますか」が出るカード）** — カメラは電圧低下などで動画を途中までしか書けないことがあり、そういうカードは Windows が「スキャンして修復」のダイアログを出す。「スキャンせずに続行」（閉じるだけでもよい）でそのまま取り込める。取り込みは全ファイルをいったんコピーしてから、中継の上で壊れたもの（途中で切れた AVI/mp4、0 バイト、終端の無い JPEG、ffmpeg が読めないもの）を見つけて取り除く（既定は消す。設定で `_破損` フォルダに残すこともできる）。壊れたファイルは NAS には送らず mp4 にも変換せず、台帳と manifest に理由を残し、「カードを消す」でカードからも消える。カードから読めないファイルがあっても、そのファイルだけ飛ばしてカードの残りは取り込む。

**裏で続く処理（任意）: 動画の変換** — 取り込み画面の「動画の変換」をオンにすると、AVI などを H.264 の mp4 に変換してから NAS へ送る。SD → 中継は元のまま検証コピー（カードを早く抜けるように）、中継の上で順に変換して元ファイルを消し、NAS へは mp4 だけ送る。MJPEG の AVI（例: 1296×720、38 Mbps）は 10 分の 1 程度になる。ffmpeg はビルドに同梱（imageio-ffmpeg）。GPU は必須ではなく、あれば自動で使う（設定の「ffmpeg とエンコーダを確認」で、各エンコーダの可否が分かる）。画質（CRF）・同時本数・エンコーダは設定で変える。

**保存済みのデータ（任意）: 動画を mp4 に変換** — 取り込み時の変換を使っていなかった頃のデータや、旧 R コードで取り込んだデータ、あるいは PC のどこにでもある AVI を mp4 にする。フォルダ（NAS の保存先ごと、区切りフォルダ、地点フォルダ、PC 上の任意のフォルダのどれでも）を指定して「対象を調べる」と、その下の AVI などを再帰的に探して、フォルダごとの件数と容量を一覧にする（まだ何も変えない）。保存先は二択で、「同じ場所に置き換える」は同じフォルダの中に mp4 を作り（`.part` に書いて長さを照合してから改名）、元ファイルを消す（容量を減らすため。不可逆）。「別のフォルダに保存する」は指定した保存先の下に相対パスを保って mp4 を書き、元ファイルはそのまま残す（manifest や台帳も触らない）。以下は置き換えのときの動き。mp4 はそのまま、Synology の `@eaDir` や `#recycle` には入らない。manifest.json があるフォルダは manifest も合わせ、台帳に記録があって変換したのが正本（NAS、NAS が無ければ中継）なら台帳も mp4 に合わせる（中継の控えを変換しても台帳は NAS 側のまま）。取り込み・NAS 転送・取り込み時の変換が途中のフォルダは対象外。同じ番号の mp4 が別にある場合は `_h264.mp4` の名前にして、カメラが作ったファイルを上書きしない。一時停止・中止ができ、中止したファイルは元のまま残って次回また対象になる。変換後に元を消す前に止まった分は、次に調べたときに元を消すだけで済ませる。画質・同時に変換する本数はこの画面で、エンコーダと ffmpeg の場所は「設定」で指定する。NAS 上で直接変換するときは、ネットワーク越しに AVI を読んで mp4 を書くので、GPU があってもネットワークの速さで頭打ちになる。

**記録・設定**
- **台帳** — 取り込み・転送・削除の記録。保存先の manifest.json から再構築できる（別PCで取り込んだ分の取り込みにも使う）。
- **設定** — 普段は変えなくてよい細かい項目だけ: カード内の対象フォルダ、壊れたファイルの扱い、検証やNAS転送の挙動、変換の画質やエンコーダ、野帳の列名、地点名の付け方（接頭辞と桁数）。値を変えるとその場で保存される。保存先・NAS・フォルダ名・変換のオンオフは「1. 取り込み」、野帳ファイルと絞り込みは「2. 地点名に変更」で指定する。

取り込み先のフォルダ名は「調査の区切り」で、同じ調査を繰り返すなら調査回ごと（N260710 のように Type と日付）、一度きりの調査なら調査地名（保尊崎 など）を入れる。フォルダ構造は `保存先/<区切り>/<カードID>/*.mp4` → 名前変更後 `保存先/<区切り>/<地点名>/*.mp4`。空にすると `保存先/<カードID>/` になる。各フォルダに `manifest.json`（ファイル名・サイズ・ハッシュ・検証日時）が置かれる。

## 他の調査・研究室で使うとき

既定値は特定の調査に依らない。必要最小限は、取り込み画面の保存先（中継）と、野帳の **Station** 列と **回収SD** 列だけ。

- 野帳は Excel でも csv でもよい。必須列は **地点名** と **回収したカードID** の 2 列だけ（設定で列名を指定）。どの行を使うかは「地点名に変更」で任意の列（Season、Type、調査地など）の値で絞り込む。設置記録との照合を使うなら **設置したカードID** の列も要る（既定 InstallationSD）。
- 取り込み先のフォルダ名（調査回や調査地）は任意。空なら保存先の直下にカードごとのフォルダができる。
- 地点名の付け方は設定の「接頭辞」と「桁数」で決める。既定は接頭辞 `BSN`、4桁（野帳の 482 → `BSN0482`）。接頭辞を空にすると数字だけ（`0482`）、桁数を 0 にすると書かれたまま。野帳の Station が番号でない文字列（Ridge-A など）はそのまま使う。
- カード内の対象フォルダは既定 `DCIM/100_BTCF`（Browning）。そのフォルダが無いカードは `DCIM` 以下をすべて探すので、他機種でもそのまま動く。設定で変えられる。
- NAS が無ければ取り込み画面の NAS 欄を空にする。保存先がそのまま最終保存先になり、削除の条件も保存先での検証済みになる。

## 配布と起動

### 学生に配る（Python 不要）

GitHub の Releases ページから、OS に合うものを 1 つダウンロードする。

- **Windows**: `camtrapdesk-windows.zip`。展開して出てくる `camtrapdesk` フォルダを好きな場所（デスクトップや D:\ など）に置き、中の `camtrapdesk.exe` をダブルクリック。フォルダの中の他のファイル（`_internal` など）は動かさない。初回は Windows の SmartScreen が「WindowsによってPCが保護されました」と出すので、「詳細情報」→「実行」。ウイルス対策ソフト（AVG など）が止めた場合は、その隔離から復元してフォルダごと除外に入れる。
- **Mac（M1 以降）**: `camtrapdesk-macos-apple-silicon.zip`。展開して `camtrapdesk.app` を「アプリケーション」に入れる。
- **Mac（Intel）**: `camtrapdesk-macos-intel.zip`。同じ手順。

Mac は署名していないため、初回に「開発元を確認できないため開けません」と出る。閉じてから「システム設定」→「プライバシーとセキュリティ」を下にスクロールし、「"camtrapdesk" は…ブロックされました」の横の「このまま開く」を押す（macOS 15 以降は右クリック→「開く」では通らない）。ターミナルで `xattr -dr com.apple.quarantine /Applications/camtrapdesk.app` としてもよい。毎回この手間を無くすには Apple Developer Program（年額）で署名と公証をする。

設定と台帳は PC ごとに `%APPDATA%\camtrapdesk`（Mac は `~/Library/Application Support/camtrapdesk`）に入る。複数の PC で取り込んだ分は、保存先の manifest.json から台帳を再構築すれば 1 台にまとめられる（「台帳」画面）。新しい版を配るときは、新しいタグを付けて Release を作り、学生にダウンロードし直してもらう。

### Release の作り方（開発者）

1. GitHub にリポジトリを作り、この内容を push する（`.venv` や `__pycache__` は `.gitignore` 済み）。
2. バージョンを上げる（`camtrapdesk/__init__.py` と `pyproject.toml`）。
3. `git tag v0.1.0 && git push origin v0.1.0`。GitHub Actions（`.github/workflows/build.yml`）がテストを実行し、Windows の exe と Mac 2 種（Apple Silicon / Intel）の app を作って、Releases に添付する（15〜20 分）。
4. 配布ページの URL（`https://github.com/<ユーザー名>/camtrapdesk/releases/latest`）を学生に知らせる。

push だけでも（タグ無し）テストとビルドは走り、Actions の画面の Artifacts から取れる。手元で作る場合:

```bash
pip install -e ".[dev]"
pyinstaller --noconfirm --clean --windowed --name camtrapdesk --paths . --collect-all openpyxl --collect-all imageio_ffmpeg tools/entry.py   # Windows → dist/camtrapdesk/（フォルダごと配る）
pyinstaller --noconfirm --clean --windowed --name camtrapdesk --paths . --collect-all openpyxl --collect-all imageio_ffmpeg tools/entry.py   # Mac → dist/camtrapdesk.app
```

### フォルダごと渡して起動する（Python が入っている PC）

- Windows: `起動.bat` をダブルクリック。初回だけ、フォルダ内に `.venv` を作って PySide6 などを取得する（数分。進み具合は黒い画面に出る）。2回目以降はすぐ起動する。Python 3.9 以上が入っていない場合はその旨が表示され python.org が開くので、インストール（「Add python.exe to PATH」にチェック）後にもう一度実行する。
- macOS: `起動.command` をダブルクリック。

実体は `tools/launch.py` で、表示は Python 側で行うのでコンソールの文字コードに左右されない。

### 開発環境

```bash
pip install -e ".[dev]"
python -m camtrapdesk
QT_QPA_PLATFORM=offscreen python -m pytest -q   # テスト
```

## 設定ファイルと台帳の場所

- Windows: `%APPDATA%\camtrapdesk\settings.json`, `ledger.sqlite`
- macOS: `~/Library/Application Support/camtrapdesk/`
- 環境変数 `CAMTRAPDESK_HOME` で変更できる。

## 運用上の注意

- Windows の自動再生（AutoPlay）は切っておく（カードを20枚挿すと20個のダイアログが出る）。
- 取り込み中・夜間転送中はPCがスリープしないようにする。
- NAS はネットワークドライブの文字を割り当てず、`\\NAS名\共有名\...` のUNCパスを取り込み画面の NAS 欄に書く。資格情報は Windows の「資格情報マネージャー」に一度登録しておく。
- 削除は「NASで検証済み」が既定の条件。NASを使わない運用（保存先をそのまま最終保存先にする）では、NAS欄を空にすると保存先での検証済みが条件になる。
- 「スキャンして修復しますか」が出たカードは「スキャンせずに続行」でよい（壊れたファイルは取り込み後に取り除く）。消したあとに Windows のスキャンをかけても差し支えない。
